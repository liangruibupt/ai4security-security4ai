# 上线前安全检查清单

精简版，逐项展开见链接的原文。

## A. AI 网关 / 模型路由（LiteLLM 等）

细节：[LiteLLM 案例 · 加固清单](../security4ai/01-litellm-case/README.md#5-ai-网关加固清单)

- [ ] 代理端口不暴露公网；管理界面和管理 API 单独监听，仅限运维网段。
- [ ] 反向代理只放行业务路由，默认拒绝 `/key/*`、`/user/*`、`/config/*` 等管理路由和 MCP 测试端点。
- [ ] 日常调用用有范围、有预算的虚拟 Key；主密钥只用于引导。
- [ ] 提供商 Key 只给推理权限，在提供商侧设用量上限和告警。
- [ ] 出站只允许到已知提供商域名，禁止访问元数据地址和私有网段；剥离客户端传入的 `api_base` / `base_url`。
- [ ] 依赖锁版本并校验哈希，每个镜像生成 SBOM。
- [ ] 告警：网关派生子进程、出站到非白名单地址、新增管理员或回调。

## B. Agent 与 MCP

细节：[MCP / Agent 威胁模型](../security4ai/02-mcp-agent-threats/README.md)

- [ ] 工具和 MCP 服务器的 token 最小权限、短期、限定 audience，不透传用户 token。
- [ ] 删除、发送、部署、付款等不可逆操作需要人工审批。
- [ ] 工具输出、网页、文件内容一律当数据，不当指令。
- [ ] 同一个 Agent 不同时具备「私有数据 + 不可信内容 + 对外通信」三项能力，至少切断一项。
- [ ] MCP 服务器固定版本、校验来源，固定工具定义的哈希，变更需重新审批。
- [ ] 本地 stdio 服务器放进沙箱，限制文件系统和网络。
- [ ] 记忆写入需确认，按用户或租户隔离。
- [ ] 保留不可篡改的工具调用审计日志。

## C. 漏洞响应准备（AI for Security）

细节：[Security Radar 深读](../ai4security/01-security-radar/README.md)、[PHP2Shell 案例](../ai4security/02-php2shell-case/README.md)

- [ ] 维护资产清单：哪些仓库、镜像、运行时版本在用，能定位到 `文件:行`。
- [ ] 订阅 CISA KEV、厂商公告、GitHub 安全公告和 OSV，信源失败要告警，不能静默成「没有新闻」。
- [ ] 真实性和紧急度由代码按证据判定；大模型生成的摘要逐句带引用并校验。
- [ ] 准备边缘缓解：WAF 托管规则组版本足够新、没有被整组设成 Count；新规则先观察再拦截。
- [ ] 自动生成的补丁 PR 一律人审，设置必需的代码所有者审核。
- [ ] 扫描器的盲区（例如 SBOM 扫描不判运行时版本）单独覆盖，结果记为「无法判断」而不是「干净」。
